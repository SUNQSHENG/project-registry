# Claude 每次会话都失忆？我用一个注册表+四条规定解决了

周一开完的会，周三打开项目，Claude 问："这个项目是做什么的来着？"

这不是段子。用 Claude Code 做项目的人大概都经历过：你上周写了一半的方案、讨论到一半的架构、改了三轮的评审材料，一切都在，除了上下文。Claude 每次启动都是一张白纸，它很聪明，但它不记得你。

我同时管着 25 个项目——培训班、医院合作、人才评审、还有几个技术项目。对我这个非程序员来说，最贵的从来不是算力，是"重新讲一遍背景"的时间。

试过各种办法：往全局配置里塞项目清单、每次开工前把背景粘一遍、建一堆文档目录。都不行，要么维护不动，要么 Claude 根本不读。

后来想明白了一件事：**Claude 不是记性差，是我没给它一个"记忆系统"**。它每次会话都会自动读项目目录里的 `CLAUDE.md`——这是它天生的记忆接口，我一直没用起来。

## 一套"注册表 + 开发记录"的架子

结构很简单，两个东西：

```
~/projects/
  PROJECTS.json          # 注册表：所有项目登记在册
  <项目>/
    README.md            # 给人看的：背景和范围
    CLAUDE.md            # 给 AI 看的：状态、决策、待办、下一步
```

`PROJECTS.json` 是一份清单，每个项目一行：序号、key、名称、状态、创建日期。25 个项目，一眼扫完。

`CLAUDE.md` 是核心。它是每个项目目录里的一份 Markdown，Claude Code 每次进入这个目录都会自动读它。我在里面固定写五块：当前状态、架构决策记录、待办、已知问题、下一步行动。

架子本身不值钱，值钱的是后面四条纪律。

## 纪律一：决策必须能追到"为什么"

以前我的项目记录只写"做了什么"：改了三版方案、加了两个功能。后来复盘的时候发现问题了——**"当时为什么这么做"全丢了**。

所以我定了条硬规则：**每条决策必须写原因，没有原因不上记录**。

```
- [✅已执行] 2026-08-08 — 单版本通用化（原因：分叉后永久同步负担；预期：零维护成本）
```

原因必写，预期可选。写上的那一刻不觉得什么，三个月后翻回来，"哦，原来当时是这么考虑的"——这就是归因。

顺带养成了另一个习惯：**重大决策当场记**。聊方案的时候说"这个就用 X 方案吧"，Claude 会问一句"这条记入决策记录吗？"——免得五分钟后忘得干干净净。日常小决定攒到保存时统一补录。

## 纪律二：会话恢复，从"回忆"变成"续接"

Claude 失忆不可怕，可怕的是每次都要重讲。现在每次打开项目，Claude 会自动做三件事：

1. 读项目的 CLAUDE.md
2. 摘要上次进展："上次做完了会员模块，CRM 对接进行中"
3. 按优先级列出下一步，问从哪继续

中断三天、三周，回来都是一句话的事。**"上次进展摘要 + 下一步行动"**——这个机制我用了之后就回不去了。

关键是保存时顺手：每次保存项目，Claude 会把本次对话的进展、决策、待办更新写进 CLAUDE.md，然后提交 git。五秒钟的事，换来的是任何时刻打开项目都有完整上下文。

## 纪律三：事后归因，一个"为什么"就能查

项目复盘的时候，我最常问的一句话是："当时为什么砍掉这个功能？"

没有记录的时候，答案永远是"忘了"。

现在有了一套归因流程：说"为什么 X"，Claude 会把相关决策按时间列出来——每个决策的原因、状态（执行了/被推翻了/搁置了）、后续影响。决策链一目了然。

对业务项目尤其有用。你改过一版报价、调整过一次合作边界，几个月后对方问"当时这个是怎么谈的"——查得到，而不是"我问问当时的同事"。

## 纪律四：健康检查和回滚，兜底

25 个项目里难免有僵尸项目：写着"进行中"，其实三个月没动了。一套内容检查会标记它们：状态矛盾、停滞过久、待办堆积、决策没落地。检查是主动的，发现问题会顺手把相关决策带出来。

误改、误删也有兜底：项目在 git 里，CLAUDE.md 有滚动备份，说一句"回滚"，对比、确认、恢复，一条链走完。**回滚本身也先备份**——回滚错了还能再回滚。

## 为什么这套对业务人也成立

说句实话，这套东西一开始是我给技术项目设计的，后来发现业务项目才是最大受益者：

- 业务项目的周期长（一个培训项目能拖半年），跨会话概率极高
- 业务项目的"上下文"是谈判口径、方案版本、审批进度——比代码更容易丢
- 业务人更不擅长"重建上下文"，因为当初的讨论往往只在聊天记录里

代码丢了可以重写，**方案口径丢了是真的找不回来**。

## 落地：一个开源 skill

这套方法我做成一个 Claude Code 技能，开源了，叫 **project-registry**。

- 安装：`npx skills add SUNQSHENG/project-registry`（或 Claude Code 里 `/plugin marketplace add SUNQSHENG/project-registry`）
- 仓库：github.com/SUNQSHENG/project-registry
- 中文界面，英文触发词也全支持

文档、示例、演示截图都在仓库里，README 有完整的使用说明。

如果你也被"Claude 失忆"折磨过，试试这套"注册表 + 开发记录"的架子——不一定用我的技能，方法本身免费。用得好，顺手给仓库点个 star，让更多人看到；遇到问题直接开 issue，我会继续改。

**最后的最后**：方法论比工具重要。工具会过时，但"每条决策写原因"和"每次保存留下一步"这两条习惯，会让任何 AI 助手都越用越顺手。
